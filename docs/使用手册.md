# 使用手册 — 蛟龙16Pro 控制协议

> ⚠️ **安全须知(必读)**: 本机型 EC 直写曾因错误格式触发 **BSOD 0x000000A5 (ACPI_BIOS_ERROR)**。
> 严格按本手册已验证的格式操作;**先读后写、每步回读验证、一次只做一个操作**。

---

## 1. 通道选择

| 通道 | 安全性 | 推荐度 | 说明 |
|------|--------|--------|------|
| **MQTT** (官方通道) | ✅ 无风险 | ★★★★★ | 走官方控制中心逻辑,不会写坏 EC |
| **EC 直写** (IOCTL) | ⚠️ 有风险 | ★★★ | 绕过控制中心直接操作 EC,用于自定义 |

**优先用 MQTT**。EC 直写仅用于 MQTT 没有的能力(自定义风扇表开关/遥测)。

---

## 2. MQTT 控制(官方通道,推荐)

### 2.1 连接参数

| 参数 | 值 |
|------|-----|
| Broker | `localhost:13688` |
| 客户端 ID | `PluginClient_1` |
| 用户名 | `PluginClient_User_1`(环境变量 `JL_MQTT_USER`) |
| 密码 | ⚠️ 本机 broker 凭证,不写入文档;运行时经环境变量 `JL_MQTT_PWD` 提供 |
| 控制主题 | `Fan/Control` |
| 状态主题 | `Fan/Status` (读) |

> ⚠️ 客户端 ID 必须是 broker 已创建的账号(`PluginClient_1` 已确认可用;
> 任意 `_N` 后缀不保证存在,`ClientIdentifierNotValid` 会被拒)。

### 2.2 模式切换

发布到 `Fan/Control`:

```json
{"Action":"OPERATING_TURBO_MODE"}    // 狂暴模式 → 0x751=0x10
{"Action":"OPERATING_GAMING_MODE"}   // 游戏模式
{"Action":"OPERATING_OFFICE_MODE"}   // 办公模式
{"Action":"OPERATING_CUSTOM_MODE"}   // 自定义模式 → 0x751=0x80
```

### 2.3 Boost

```json
{"Action":"FAN_BOOST_ON"}            // Boost 开启 → RPM ~5284, 0x751=0x40, 0x768=0x04
{"Action":"FAN_BOOST_OFF"}           // Boost 关闭 → 回 ~3796
```

### 2.4 自定义风扇曲线

```json
{
  "Action": "SET_FAN_SPEED_CURVE_SETTING",
  "Name": "M4T1",
  "Type": "CPU",
  "T0": "30", "T1": "30", "T2": "35", "T3": "40",
  "T4": "45", "T5": "50", "T6": "55", "T7": "60",
  "T8": "65", "T9": "70", "T10": "75", "T11": "80",
  "T12": "85", "T13": "90", "T14": "95", "T15": "100"
}
```

⚠️ 两个坑:
1. **`Type` 必须大写** `"CPU"`/`"GPU"` — 小写 `"cpu"` 会被静默忽略
2. **首点(最低温度)必须 0%** — 否则 EC 拒绝整表(回退内置曲线,风扇不跟随)。`MqttControl curve` 已自动强制
3. **先发 `OPERATING_CUSTOM_MODE`,停 ~1.5s,再发曲线** — 顺序反了会被模式切换覆盖

✅ **实测已验证(2026-08-05)**: MQTT 写 `T0:"0",T1-T15:"100"` → 风扇拉满(4739 RPM,88.5%);
首点写 100% → 表被拒(输出不跟随)。单位: 占空比值÷2=百分比(0xC8=200=100%)。

### 2.5 查询

```json
{"Action":"GET_FAN_SPEED_CURVE_SETTING"}    // 读当前曲线
{"Action":"GET_FAN_STATUS"}                 // 读风扇状态(经 Fan/Status 返回)
```

### 2.6 键盘背光 (✅ 2026-08-05 逆向, 主题 Keyboard/Ctrl)

```json
{"function":"Init"}                                    // 初始化会话(点灯前提!实测必需)
{"function":"SetPower","powerstatus":1}                // 开背光 (0=关)
{"function":"SetLightingLevel","light":"4","mode":"Lighting"}  // 亮度 0-4
{"function":"SetEffectALL","effect":"Breathing","mode":"Lighting","speed":"2"}  // 效果
{"function":"SetPower","powerstatus":0} + {"function":"DeInit"}  // 关 + 清理会话
{"Action":"GETSTATUS"}                                 // 查询状态
```

- **消息格式:控制用 `{"function":...}`,查询用 `{"Action":...}`**
- **必须先 `Init` 再控制**——否则只有状态变化,物理灯不亮(实测);`DeInit` 配对应答,乱序会触发控制台 UI NullReferenceException
- **亮度范围 0~4**(不是 5)
- **有灯光休眠功能**(当前默认 5 分钟)——灯自动熄灭可能是休眠定时器,不是故障;动作 `KEYBOARD_LIGHTBAR_TIMER_ON` 疑似休眠开关
- 效果枚举: Single / Breathing / Wave / Reactive / Rainbow / Ripple / Raindrop / Marquee / Impact / Spark / Aurora / Music / UserMode / Gaming / Flash / Mix / Thinking / Devour / Manual / ColorfulWave / Dawn / ColorMarquee / Twinkling / Sine / Interlace
- 方向: LeftRight / RightLeft / DownUp / UpDown / OnKeyPressed / Sync
- 命令行: `dotnet run --project tools/MqttControl -- kb on|off|bright <0-4>|effect <名字>|status`

## 3. EC 直写(自定义控制,有风险)

### 3.1 设备与 IOCTL

| 项 | 值 |
|----|-----|
| 设备路径 | `\\.\ACPIDriver` |
| 读 IOCTL | `0x9C40A488` — 输入 `[addr:4]`,输出 buffer,结果在 `out[0]` |
| 写 IOCTL | `0x9C40A48C` — 输入 `[addr:4][value:4]` |

### 3.2 已验证格式(C# 示例)

```csharp
// 读 EC 寄存器
byte[] ReadEC(IntPtr h, ushort addr) {
    byte[] input = BitConverter.GetBytes((uint)addr);   // 4字节地址, 小端
    byte[] output = new byte[4];
    DeviceIoControl(h, 0x9C40A488, input, 4, output, 4, out _, IntPtr.Zero);
    return output[0];
}

// 写 EC 寄存器
void WriteEC(IntPtr h, ushort addr, byte value) {
    byte[] input = new byte[8];
    Array.Copy(BitConverter.GetBytes((uint)addr), input, 4);  // 前4字节=地址
    input[4] = value;                                          // 后4字节=值
    DeviceIoControl(h, 0x9C40A48C, input, 8, null, 0, out _, IntPtr.Zero);
}
```

### 3.3 安全规则(血泪教训)

1. ❌ **禁止**把 40 字节 `"AeiC"/"ECRR"` 结构**直接当 IOCTL 输入**发给 `0x9C40A48C` —
   驱动会把输入**前 4 字节当 EC 地址**,读到垃圾高地址 → **BSOD 0xA5 的根源**。
   (正确的 ACPI EVAL 结构由驱动内部构建,用户只需传 `{addr}` / `{addr,value}`。)
2. ❌ 禁止猜测格式盲扫 — 每次只测一种已验证格式
3. ✅ **每次写后立即读回**验证
4. ✅ 只写已知地址(见下);不要枚举未知地址
5. ✅ 操作前关闭 MQTT 控制台竞争(避免双方抢写同一寄存器)

### 3.3b ⚠️ 固件写保护边界 (2026-08-05 穷尽测试)

| 区域 | 直接写 | 说明 |
|------|--------|------|
| 0x751 模式 / 0xD8 / 0xD9 | ✅ 可写 | 已验证 |
| **风扇表 0xF2/0xF5/0xF00~0xF5F** | ❌ 固件硬保护 | 24 IOCTL × 各种格式/解锁/标志地址全部被拒 |
| 0x768 Boost 触发 | ❌ | 仅 GCUService/MQTT 可置位 |

**结论:风扇表只能通过 GCUService(MQTT 命令)写入**。直接写 EC 改曲线不可行。

### 3.4 直写示例序列

```text
读遥测:    读 0x464/0x465 → CPU RPM (大端: 0x464<<8 | 0x465)
读模式:    读 0x751 → 0x10=TURBO, 0x40=BOOST, 0x80=USER
切模式:    写 0x751 = 0x10   (切 TURBO)
启用表:    读 0x7C5 → 置 bit7 → 写 0x7C5   (SetEcFanControlRespective 逻辑)
写曲线:    写 0xF2+i (i=0..15) = CPU 占空比曲线 (单位 0.5%, 0xC8=100%)
           写 0xF5+i (i=0..15) = GPU 占空比曲线
           首点(最低温度)强制 0%; 曲线必须单调递增
           温度点固定: CPU=0xF40区(44~80°C), GPU=0xF00区(推定48~85°C)
应用表:    写 0x7C6 = 0x04
```

> ✅ **实测已验证(2026-08-05)**: 写 0xF2(CPU)/0xF5(GPU) 占空比区 → 转速实时跟随,
> 与控制台 UI 设置 100% 吻合(全 100% → RPM 5272;调低 → 4922)。
> 之前 "曲线不驱动转速" 的结论是错的——原因是 MQTT 把曲线写到了 0xF00/0xF10 错误区域。

## 4. 遥测读取

| 地址 | 含义 | 说明 |
|------|------|------|
| `0x464`/`0x465` | CPU 风扇 RPM | 大端: 0x464<<8 \| 0x465 |
| `0x46C`/`0x46D` | GPU 风扇 RPM | 大端 |
| `0x75B`/`0x75C` | 占空比显示 | 0.5% 单位(0x91 ≈ 72.5%) |
| `0x449`/`0x44C` | 温度 | °C(比控制台显示低约 10°C,偏移未明) |
| `0x783`/`0x784`/`0x785` | PL1 / PL2 / PL4 | 功耗墙 |
| `0x786` | TCC | 温度墙 |

## 5. 快速验证清单(拿到机器后 2 分钟确认通道正常)

```text
1. MQTT 连上 → 发 OPERATING_TURBO_MODE → 读 0x751 应为 0x10 ✓
2. MQTT 发 FAN_BOOST_ON → 读 0x464/0x465 应 ~5284 RPM ✓ (0x768=0x04)
3. MQTT 发 FAN_BOOST_OFF → RPM 回落 ✓
4. EC 直写读 0x751 → 与 MQTT 状态一致 ✓
```

全部通过 = 两个通道都正常。
